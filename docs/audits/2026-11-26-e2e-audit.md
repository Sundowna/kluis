## Broken features (found broken; fixed after Walter's OK)

- **F-022 / F-021 — names that Windows tells apart but Python's `casefold()` doesn't.** `fit_windows_names`
  (`kluis/engine.py`) groups names with `str.casefold()`, which turns `ß` into `ss`. Windows (NTFS) compares by
  upper-casing each character on its own and keeps `straße.txt` and `strasse.txt` apart. Two effects, both
  reproduced on this PC with the mock CLI:
  1. `straße.txt` next to `strasse.txt` in Proton Drive: one is *left out* ("differs only in upper and lower case")
     although Windows can store both.
  2. `STRASSE.md` on this computer next to `straße.md` in Proton Drive: the local file is renamed in the plan to
     `straße.md`, which doesn't exist on disk, so **the whole folder fails every sync** with
     `[Errno 2] No such file or directory: …\straße.md`. Nothing is lost, but the folder never syncs again until
     one file is renamed. The ledger promises "the rest of the folder syncs".
  Broken since 2ec033e (the port). Test: `tests/test_windows.py`, section "names Windows tells apart" (failed
  before the fix). **Fixed** in ff0a99a, with Walter's OK:

  ```python
  # kluis/engine.py: used instead of .casefold() in fit_windows_names
  def _win_case(name: str) -> str:
      """Windows (NTFS) compares names by upper-casing each character on its own: ß stays ß, unlike casefold()."""
      return "".join(u if len(u := c.upper()) == 1 else c for c in name)
  ```

## For you to decide (no todo tests: these are questions, not bugs)

- **A folder renamed only in letter case in Proton Drive** (`Docs` → `docs`) holds the folder with the usual guard
  ("Kluis is about to move 20 files … to the trash"); after you agree, the local copies go to the Recycle Bin and
  come down again under the new name. That is exactly what Kluis does for *any* folder renamed in Proton Drive
  (Linux too: the engine has no remote-rename detection), so it is not a port regression. Should Windows apply a
  case-only rename as a plain rename, without the guard? A case-only rename of a *file* already works quietly
  (old copy to the Recycle Bin, new one downloaded).
- **Paths longer than 260 characters.** Not checked: this PC has `LongPathsEnabled = 1`, so the limit can't be
  reproduced, and whether the PyInstaller-built `Kluis.exe` declares itself long-path aware wasn't checked either.
  On a PC without long paths a deep Proton Drive folder would probably give per-file errors.

## CI change

All three jobs ran the suites one after another and stopped at the first failure, and the GUI flows step had no
`if:`, so **one failing check skipped all 108 GUI flows** on that platform. Now each test step runs every suite
(including the new `test_windows.py`) and fails at the end if any failed, and the flows steps (and the Windows
screen-size step) run `if: !cancelled()`, like the Windows build steps already did ("every result in one run").
(The audit commit alone was red on the F-022 check by design; the fix follows in the next commit.)
